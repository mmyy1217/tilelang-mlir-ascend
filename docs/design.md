# 算子知识与实验服务：设计文档

版本：0.6 · 2026-11-02 · 设计与实现边界

需求依据：[需求文档](requirements.md)。当前目标是可上线分享的 Web 工作台：记录多 Agent 探索图、展示节点内的 stage 状态机，并联动浏览文件与引用。当前不实现审批、远端合入或自动冷却。

## 1. 技术与部署

采用一个 Web 前端、一个轻量 API 服务和本地持久化存储，不引入独立消息队列、图数据库或向量服务。

| 部分 | 建议技术 | 用途 |
|---|---|---|
| 前端 | React + TypeScript + Vite，普通 CSS | 浏览器工作台，构建为静态文件 |
| 探索图 | React Flow | 自定义节点、可点击边、缩放与选择 |
| Agent 视图 | React 组件与 CSS 时间轴 | 按 Agent 展示节点和 stage 执行轨迹，不另引图表框架 |
| 后端 | Python + FastAPI + Uvicorn | 数据校验、HTTP API、事件推送、停止协调 |
| 存储 | SQLite + 文件目录 | 结构化记录、事件及不可变产物，无独立数据库服务 |
| 实时更新 | HTTP 写入 + SSE 推送 | Agent 上报结果，浏览器订阅变化 |

前端构建后由后端同源托管，运行时只需一个服务。开发时前端通过代理访问 API。支持 Windows、macOS、Linux 上本地运行；实际内核编译与设备测试由外部 Agent 在对应环境执行，不要求浏览器或 Web 服务拥有 NPU。

上线使用同一应用的单容器或单进程部署，挂载持久化数据目录，通过 HTTPS 分享任务链接。首版采用单实例、单 API 进程和短事务写入；多 Agent 并发请求经服务串行协调数据库写操作。SQLite 启用 WAL，为每个连接配置 busy_timeout；仍保持单写入者和短事务，超时返回可重试错误，不保证完全无锁等待。暂不支持无持久磁盘的无状态部署或多个实例共享 SQLite 文件。

查看者使用只读访问权限，Agent 使用写入凭据，停止操作仅开放给任务操作者。非公开任务及文件均检查访问权限；写入凭据不放入分享 URL。首版无需完整团队角色系统。

Agent 实例定义为一个持续迭代并最终交付的 session，使用稳定的 Agent/session ID。角色描述其策略或功能，不作为身份；同一 session 可参与多个节点或阶段，新 session 使用新身份，恢复同一 session 保留原身份。图展示 stage 各次尝试的执行 Agent；Agent 轨迹支持逐个及全部折叠，并保留视图切换时的折叠状态。

### 探索图与 session 解耦

探索图是探索优化的持久事实来源，独立于任何 Agent session。核心层级为 Project/Exploration → Node → Stage → Attempt；Agent 通过 Attempt 参与执行，其创建、退出、替换和重新编排不改变探索图结构与既有证据。Node.agentIds 是参与历史，不是所有权或执行许可；一个节点通常由一个 session 推进仅是默认策略。工具执行器不因执行编译或评测就自动成为智能体。

建议的编排是主 Agent 选方向，探索 session 独立推进，harness 校验预算和执行条件，外部启动适配器创建 session。首版不要求 Worker 自行递归派发；策略可以改变，数据库不绑定固定 Agent 拓扑。目标、任务分配、预算、阻塞与交付应持久保存，使主 Agent 也可替换；完整派发/接手任务记录和真实 session 启动适配器仍待接入。

随时暂停表示停止发放新许可并保存已登记的状态，不承诺恢复未写出的进程内存。在途任务必须取消、收尾或核对，不能因 session 断开就判定设备停止。恢复前检查未结束的 Attempt 和预留额度；新 session 登记独立 ID，基于已有结果追加 Attempt，不能改写历史执行者。

## 2. 数据结构

核心层级为 **探索图 → 节点 → stage → 执行尝试与资源引用**。图与 Agent 视图是同一数据的两种展示，不各存一套记录。

| 对象 | 核心内容 |
|---|---|
| Exploration | 优化目标、输入与环境、固定基线引用、预算、停止规则、当前状态 |
| Node | 所属探索、多个来源方案（无来源时为独立起点）、优化思路、改动说明、kernel 引用、参与 Agent、执行状态 |
| Stage / StageAttempt | 节点内阶段类型、每次执行的 Agent、状态、开始结束时间、依赖的上游 attempt、输入输出资源版本、结果与失败/跳过原因 |
| Agent | session 身份、名称、心跳；通过执行尝试关联节点与阶段，不拥有节点；Fork 中可仅作为历史身份 |
| Project / Folder | 项目目录项与一级文件夹；本地快照或服务端探索引用，展示名称、更新时间、Fork 来源 |
| Resource | kernel、思路、总结、实验、profile 等内容的稳定 ID、版本、类型、哈希与文件引用 |
| ResourceLink | 节点或执行尝试使用的资源版本、输入/输出角色与来源；同一资源允许多个引用 |
| Reference | 引用方节点、被引用的节点/知识/实验及其版本、引用说明和用途（派生依据或跨分支参考）；不等同于派生／融合 |
| Knowledge | 基础知识或优化经验、正文版本、适用条件、支持节点与反例 |
| Event | 探索内递增序号、事件 ID、对象版本、变化类型和数据，用于恢复与同步 |

实验记录保存环境、参考实现、容差、测量方法和结果，profile 作为可选结构化摘要及原始文件引用；缺失时明确显示。资源按不可变版本保存，更新产生新版本，不改写已完成尝试的引用。

基础知识、实验相关内容和优化经验均具有 hot/cooled 状态。ready-for-cool 是 hot 内容的候选标记，与节点和 stage 的执行状态独立。当前只整理和展示候选；已存在的 cooled 基线按固定版本只读引用，不提供转换为 cooled 的接口。

GraphRelation 是一等关系：sourceType/sourceId、targetType/targetId、kind（derivation/reference/support/refute）、rationale、可选 resourceVersionId、knowledgeVersion 与 evidenceAttemptIds。派生仅连接方案；支持/反驳从方案指向知识并要求该方案已结束的实验 Attempt；参考描述实际借鉴，不升级为因果证明。知识端点要求精确版本，跨项目端点拒绝。

方案支持多个来源；只有派生子图要求 DAG，参考和证据关系不参与派生环检查。Node.parentIds 是派生关系的读取投影，不是固定主父树。图布局按所有来源的最长派生层级计算，知识和经验保留独立数据身份，但不作为画布节点；在方案右侧的“基础知识与优化经验”中查看内容及全部来源和使用。画布只显示方案之间的派生／融合和参考关系；连线标签避让方案卡片并保持可点击。

兼容旧数据：保留数据库 parent_id 和旧 references 读取，统一投影为 graphRelations；旧 parentId 仅兼容输入，不再规定唯一父节点。新增 graph_relations 表保存显式类型关系，新接口 POST /api/explorations/{id}/relations；新的 Node 可传 parentIds。支持/反驳的旧知识数组只作为既有证据主张投影，不自动升级验证等级。

## 3. 节点状态机与停止协调

默认 stage 顺序：

```text
读取信息 → 形成优化思路 → 生成 kernel → 编译
        → 正确性验证 → 性能测量 → profiling → 获取结果并总结
```

每个阶段具有 pending、running、completed、failed、skipped、stopped 状态。开始执行产生一个 StageAttempt；重试追加尝试并保留旧记录。跳过须说明理由，未通过正确性验证的结果不能进入最佳有效 kernel 排名。失败后可记录诊断总结，不能伪装成完整成功链路。阶段修复保留代码版本，新的优化方案创建子节点。

编译或验证失败后，允许回退到生成 kernel 等上游阶段修复，再执行下游阶段。每次 StageAttempt 明确引用所依赖的上游 attempt 和资源版本，例如生成 G2 → 编译 C3 → 验证 V2 均对应 kernel v2；轮次号仅用于展示分组，不替代依赖关系。仅重测性能时可以复用匹配的编译与验证结果；代码更新后，旧结果保留为历史，不得作为新代码的验证依据。UI 按实际依赖展示回退、重试和结果归属。

外部 Agent 作为 HTTP 客户端主动创建节点、申请阶段执行许可、周期性心跳并上报状态与结果。服务批准后创建执行尝试，校验阶段前置条件和当前版本；同一尝试只允许一个执行者，多 Agent 可并行处理不同节点。事件记录可公开的思路与依据，不要求模型隐藏思维链。

协调逻辑放在 API 服务内：外部 Agent 在创建节点或启动尝试前申请许可，服务事务性检查并预留预算，完成后结算。预留中的任务也计入预算，避免并行超发；Agent 执行与硬件测试仍在外部完成。

按需求执行目标达成、预算耗尽、用户停止、分支停滞和全部分支结束规则。停止先禁止新许可，再在心跳或状态上报响应中向在途 Agent 返回停止指令。Agent 即使在长时间实验期间也需维持独立心跳；取消由执行器协作完成，响应延迟受心跳间隔与执行器取消能力影响，无法立即取消的实验允许收尾并上报。首版 SSE 仅供浏览器订阅，不另建 Agent 推送控制通道。仅收到停止请求时显示 stopping，确认收尾后才显示 stopped。心跳失联标记未知或中断，不假定设备已经停止；重连后核对尝试状态。

保存停止原因、最佳有效节点和未完成方向。重启从数据库恢复预算、尝试和事件，不自动重新派发可能仍在运行的实验。

## 4. 工作台布局与联动

顶部仅显示算子名；契约以 YAML 展开，输入 Shape 以分组列表展开，环境分项展开。基线与当前最佳耗时紧凑并列，预算、运行及连接状态常驻。契约包含优化目标、参考实现与精度容差、预热与重复次数、计时边界和同步方式；关联文件保留版本，未配置项不推断，实际实验协议不替代约定。最左侧是项目栏，主体为可调整宽度的左右分栏。停止 API 已有，当前界面尚未提供执行控制入口。未选中节点时主要显示视图，选中后右半部展开文件库。窄屏以抽屉展示详情。

- **左侧图**：方案派生 DAG 采用分层图布局；卡片显示方案、Agent、当前 stage、执行状态和内容标记。展开节点显示内部状态机及尝试历史。默认隐藏跨分支引用，选中时按需展开；点击边查看派生依据或具体引用。
- **左侧 Agent 视图**：每个 Agent 一条时间轨迹，展示其参与的节点及 stage 尝试；多个 Agent 参与同一节点时仍使用同一节点 ID。
- **右侧文件库**：按 kernel、优化思路、总结、实验记录、profile 和其他产物分组。选中 stage 时定位其输入输出，允许返回节点全部资源。共享文件标注来源、版本和其他引用节点。
- **预览**：文本和代码只读展示；Markdown 安全渲染，禁用任意 HTML/脚本；大日志分页加载，无法预览的二进制 profile 提供元数据与受控下载，不假装已解析。

两种视图共用一个规范化数据状态和 selection（node_id、stage_id、attempt_id、edge_id）。切换只改变展示方式，保留选中对象、展开状态和各视图视口；新事件增量更新数据，不强制重排用户正在浏览的图。派生子图初始布局独立于引用边，新增分支局部布局，提供手动重新布局入口。

执行状态使用颜色、图标和文字；hot、ready-for-cool、cooled 使用独立徽标，提供图例。节点比较先显示代码、环境与验证协议，再展示可比结果。引用缺失、文件未生成、实时连接断开都明确显示，不显示空白成功状态。

任务链接可携带选中节点和 stage，便于分享后直接定位；链接只改变定位，不赋予访问权限。

### 项目栏与截面 Fork

左侧增加独立于双视图的可折叠项目栏，提供项目创建、导入、选择、重命名、一级文件夹、拖动归类及键盘可用的“移至”操作。目录与本地项目快照使用 IndexedDB，写事务成功后再切换界面；不复用单个 localStorage 槽位覆盖项目。localStorage 仅保存当前项目、栏折叠等偏好。服务端项目列表从 `/api/explorations` 读取，本地保存其最近快照；实时状态仍以服务端为准。

Fork 深拷贝当前已保存快照，产生独立 Exploration ID，记录 `forkSource`（来源 ID、标题、事件水位、时间）。节点、资源、Attempt 的局部 ID 及依赖保持，所属 Exploration 改为新项目。已完成证据不变；在途 Attempt 在副本内转为 stopped 并保留 sourceStatus 和截面中断原因，不表示源执行已停止；Agent 仅保留历史身份。预算保留已有使用量，清空在途预留；副本等待接手，不自动恢复或启动执行器。服务端快照通过同一 SQLite 读事务获取图与事件水位，避免混合两个时间截面。

空项目不伪造根节点或实验结果，显示待创建方案的空状态。切换项目关闭原 SSE、取消旧快照请求、重置选择与事件水位；异步旧响应不得污染新项目。项目栏本次提供浏览器本地管理，不是服务端项目导入/发布 API；这些本地项目需后续显式接入执行服务才可由外部 Agent 继续写入。

## 5. API、实时更新与文件

| 接口组 | 当前能力 |
|---|---|
| 探索 | 创建、读取状态、读取初始快照、请求停止与显式恢复 |
| 节点与尝试 | 创建子节点、申请执行许可、心跳与上报状态/结果、响应继续或停止指令、读取依赖与历史 |
| 资源与引用 | 上传下载资源、关联节点或 stage、读取跨分支引用 |
| 知识与候选 | 按类别与状态查询、保存总结及证据、标记 ready-for-cool |
| 事件流 | 按探索订阅 SSE，从指定事件序号补发 |

API 校验图结构、对象归属和精确引用；写入携带唯一请求 ID，重复请求返回已有结果，不同载荷复用 ID 报冲突。并发修改携带对象版本，过期修改拒绝覆盖。

状态更新与事件在同一 SQLite 事务提交。浏览器先读取带事件水位的快照，再从该水位订阅 SSE；按序号去重，断线后续传。历史不可补齐时重新读取快照，保留仍有效的选中对象。SSE 只传元数据变化，文件按需加载，设置心跳并关闭部署代理的流式响应缓冲。事件补发分批读取，每批完成即释放读事务；等待新事件或向网络发送数据时不持有数据库事务，避免长期读事务妨碍 WAL checkpoint。

上传先写临时文件并校验哈希，再登记资源和引用；失败留下的未引用临时文件延迟清理。通过资源 ID 读取文件，不暴露服务器路径；被节点引用的文件不能作为临时缓存删除。SQLite 文件和产物目录共同构成持久化数据，备份时使用一致数据库备份并保留其引用文件。

### Skill 与 CLI 入口

提供一个 skill 包，包含短 SKILL.md、CLI 和按需参考；不额外要求 MCP。CLI 经 HTTP 接入现有服务，Web 经快照/SSE 查看同一数据。harness 的协调代码不是主 Agent；服务本身不负责启动模型。CLI 不逐接口机械翻译，优先提供 context、方案创建、Attempt、资源和交接等意图明确的动作。

实现位于 [skill 包](../skills/operator-exploration/SKILL.md)，[CLI 协议](../skills/operator-exploration/references/cli.md) 是实际可执行接口。Python 3.10+ 标准库客户端，YAML 输入可选 PyYAML；通过包安装提供 `opwork`，也可直接运行脚本，不增加服务中间件。

独立上下文绑定服务/项目/session；JSON 输出、提交前请求日志及精确重放防止重复登记。资源上传与下载校验哈希。后台 helper 每 5 秒心跳，外部执行器负责响应 stop 并上报终态；心跳不是设备进程监控。关闭 session 持久登记且拒绝重新激活，operator 可核对并终结遗留尝试，不能据此上报成功。

服务提供有界 context、持久 handoff、一致 checkpoint 和原子 fork。Fork 保留服务端有效证据并清除副本的在途执行状态，源项目不变。导入采用新项目 ID，验证资源和关系；历史正确性声明不直接参与排名，保留来源并要求重新验证。浏览器本地项目须导出后显式导入服务端。项目目标/预算在线 configure、自动派发、递归来源查询尚未实现，能力握手及命令会明确说明。

当前使用单工作区共享凭据，session 是归属身份而非安全隔离边界。独立 session 权限与多租户不在本轮范围。

Summary 和 `.md`/`.markdown` 文件使用 React Markdown + GFM 渲染，支持表格与代码块；不启用原始 HTML，链接使用安全 URL 处理，图片不自动向远端发请求。代码资源维持纯文本预览；Markdown 原文仍保存于不可变资源版本。

## 6. 当前实现与验收顺序

1. **可分享交互原型**：用固定样例数据完成图、Agent 视图、stage 展开、右侧文件库和引用边。原型可作为静态 Web 页面部署，明确标记演示数据，不具备真实停止或同步能力。
2. **真实记录与实时同步**：接入 API、SQLite、资源目录和 SSE，使用两个 Agent 模拟器并行写入，验证节点内阶段、回退修复与 attempt 依赖、共享文件、派生依据与跨分支引用、断线续传与页面定位。
3. **当前闭环**：接入真实外部执行器，验证预算及停止规则、中断恢复、结果与总结记录、ready-for-cool 展示。发布版使用持久化 Web 服务，部署地址与分享内容另行确定。

验收以需求文档第 6 节为准；不包含人工审批、远端合入和跨任务收益评测。完整多租户、复杂调度、图数据库与跨实例同步不进入当前实现。

## 7. 技术依据

- [React Flow 自定义节点](https://reactflow.dev/learn/customization/custom-nodes)：用于节点卡片与选择交互；节点内部 stage 是业务数据，不借用画布分组代替状态机。
- [Vite 静态部署](https://vite.dev/guide/static-deploy)：支持先上线交互原型，再由 API 服务托管同一前端构建产物。
- [FastAPI 容器部署](https://fastapi.tiangolo.com/deployment/docker/)：用于单服务部署；持久化目录、HTTPS 和访问权限需在部署时配置。

- [SQLite WAL](https://www.sqlite.org/wal.html)：改善读写并发，仍需处理忙等待并避免长读事务。
