# 算子知识与实验服务：需求文档

版本：0.4 · 2026-11-02 · 需求与当前交互范围

## 1. 目标与边界

本项目是供人和不同优化 Agent 共用的算子知识与实验服务：让下一次优化利用已有证据，减少重复探索，避免误用其他环境下的经验。

首个领域是 TileLang 算子优化，可面向 Ascend；公共协议不绑定具体 Agent、编译器或代码层级。外部负责生成、编译和运行内核，服务负责保存、查询、整理和核验知识。人和 Agent 均通过服务接口操作，不直接访问底层存储。

Agent 实例定义为一个持续迭代并最终交付的 session，使用稳定的 Agent/session ID。角色描述其策略或功能，不作为身份；同一 session 可参与多个节点或阶段，新 session 使用新身份，恢复同一 session 保留原身份。图展示 stage 各次尝试的执行 Agent；Agent 轨迹支持逐个及全部折叠，并保留视图切换时的折叠状态。

**探索图与 Agent 独立**：Node、Stage、Attempt 及其资源是探索的持久核心；Agent 是可替换的执行 session，通过 Attempt 关联探索图。Agent 可跨节点、跨阶段；具体分工由主 Agent 决定，节点负责人只是可调整的编排策略，不是永久身份绑定。探索图的派生关系与 Agent 的委派关系互不决定。

探索图可以随时请求暂停并保存已登记的状态，由全新 session（包括新的主 Agent）接手。恢复依据必须存于探索图与持久化协调记录，包括目标、预算、任务分配、结果、阻塞和未完成方向，不能依赖原 session 的私有对话。历史 Attempt 保留原执行者，新 session 追加新 Attempt；在途外部任务先核对、取消或收尾，未确认停止不能当作已完成。

## 2. 系统要素

系统管理基础知识、实验相关内容和优化经验三类要素，每类都分为 **hot** 和 **cooled** 两种状态：

- **hot**：当前正在开发和优化的 kernel 所获得的内容，包括已验证的结果和尚待验证的认识，随探索持续更新。
- **cooled**：经过验证、人工审批并合入远端主线的内容，供后续任务复用。仅完成实验、结束任务或上传远端，都不会自动变为 cooled。

| 要素 | hot：当前 kernel 的工作内容 | cooled：已验证并合入远端主线的内容 |
|---|---|---|
| 基础知识 | 当前任务收集和整理的算子语义、硬件约束、工具链与 API 信息，以及待核实的理解 | 经核验的基础资料与约束，保留来源、版本和适用条件 |
| 实验相关 | 以 探索图组织当前 kernel 的探索；每个节点包含 节点的 stage 状态机、当前优化方案下的 kernel、实验记录及独立或共享产物的引用，支持多 Agent 并行扩展分支 | 经核验并合入的 探索图或选定分支，以及节点关联的 kernel、实验记录与必要产物，保留探索路径和证据引用 |
| 优化经验 | 当前任务形成的策略、猜想、失败解释和阶段性结论 | 经证据验证的优化方法与经验，说明适用范围、支持证据、反例和未验证范围 |

**hot → cooled 必须经过人工审批**：人检查内容及其证据的正确性，可以直接批准，也可以要求修改或补证后再批准；批准并合入远端主线后才成为 cooled。失败实验也可作为经核验的记录保留，不表示其代码通过了正确性测试。

三类要素可分别选择合入，但相关引用和必要证据必须完整；不要求整次探索全部合入。未获批准的内容继续保留为 hot，或按策略归档。cooled 的后续修订仍需经过验证与人工审批；本地缓存 cooled 内容不改变其状态。

## 3. 核心流程

**探索图是实验相关内容的基础结构**。一次 kernel 优化形成一个图：方案节点代表一个具体优化方案，知识节点代表基础知识或优化经验，方案派生关系表示从已有方案派生出新的尝试。它既组织多 Agent 发散、并行推进的过程，也为最终解释优化路径、比较分支和总结经验提供依据。

每个节点包含当前方案的 kernel、相对来源方案的改动与意图、参与执行的 Agent 历史、实验状态，以及实验记录和产物的引用。实验记录说明环境、正确性与性能结果；代码、输入、日志等资源可以由节点独立持有，也可以被多个节点共同引用，无需重复复制。引用指向明确版本，共享资源不因某个分支的修改而改变其他节点的历史。资源共享不改变探索图的方案派生关系。

**stage 是一个节点内部的工作阶段**，层级为“探索图 → 节点 → stage”。每个节点记录完整的推进过程：读取已有信息与优化依据 → 形成优化思路 → 生成 kernel → 编译 → 正确性验证 → 性能测量 → profiling → 获取结果并总结。每个 stage 通过 Attempt 记录执行状态、实际执行的 Agent、输入与输出资源引用及结果；允许失败、重试或有明确理由的跳过，保留实际状态转换历史。重试保留代码与产物版本，不覆盖此前结果；新的优化方案通过子节点继续探索。

方案允许从多个已有方案派生或融合，也可以作为独立起点。方案派生关系必须无环；知识、经验作为独立的关联要素，通过参考、支持、反驳关系关联方案及实验。关系保存来源版本、具体贡献和证据；参考不等同于实验证实有效，支持与反驳不自动证明因果。采用其他方案的改动后必须重新验证。

1. **建立根节点**：明确优化目标、输入与环境，固定所引用的 cooled 基线，将初始 kernel 及其已有实验记录关联到根节点。开始前约定全局预算、目标达成条件和分支停止规则。

2. **多 Agent 分支探索与实验**

   - **扩展方案**：Agent 从选定节点提出优化方案并创建子节点，记录改动与依据；多个 Agent 可从同一节点并行探索，或沿已有分支继续扩展。
   - **执行实验**：Agent 按节点内部的 stage 状态机推进，外部 Agent 或评估器执行编译、正确性验证、性能测量和 profiling，将状态转换、实验记录及资源引用写回对应节点和 stage。
   - **反馈推进**：保留成功、失败、变慢和未完成的尝试，根据结果选择下一步方案、继续分支或恢复中断的探索，并持续检查停止条件。

3. **判断继续或停止**：统一任务协调者管理全局预算、控制新节点创建并汇总分支状态，执行以下规则。

   - **目标达成**：达到预设正确性与性能目标时，按任务约定结束整个图的探索。
   - **预算耗尽或用户停止**：时间、设备评估次数或成本预算耗尽，或用户主动停止时，必须停止整个图的扩展。
   - **单个分支停止**：连续若干次无有效收益、重复已有方案或遇到无法解决的限制时，可以停止该分支，其他分支继续。收益判断窗口和阈值可配置，并考虑测量波动。
   - **全部分支结束**：所有分支停止且无待执行任务时，整个图结束探索。
   - **停止后收尾**：不再派发新任务，在途实验按取消策略终止或收尾并记录状态；保存探索图、当前最佳且正确性通过的 kernel 及证据、停止原因和未完成方向。没有有效结果时明确说明；探索停止不代表成功，也不会使 hot 自动变为 cooled。

4. **总结探索图并提炼优化经验**

   - **解释探索过程**：综合整个图的成功路径、失败分支和反例，说明各方案的改动、继续或停止的依据，以及可比条件下的效果差异。
   - **提炼可复用经验**：从上述比较中形成优化经验，关联具体节点及证据，明确适用条件和未验证范围；未经证实的原因保留为假设。

5. **整理待冷却候选**：从探索图中选择基础知识、实验相关内容和优化经验，整理来源与必要证据，形成 ready-for-cool 候选供查看；当前流程到此结束，不执行人工审批或合入。

远端更新不自动改变正在进行的探索；更新基线须显式操作并检查冲突。共享只包含选定变化及必要证据，不默认上传完整工作区、日志和临时文件。目标无法访问的证据不能算已交付。

保存探索、接受知识和发布外部 PR 是不同操作。新建、重新打开或发布 PR（含 draft 和 mark ready）必须取得用户对本次具体仓库及具体 PR 操作的直接明确授权；旧授权、push 授权、核验接受和任务完成均不能替代。

## 4. UI 平台

当前优先做好探索过程的可视化布局和交互，暂不实现人工审批及合入操作；前述 hot → cooled 规则保留为后续流程。用户能够从整个探索图或单个 Agent 的完整过程出发，逐层查看节点、节点内部的 stage 和相关资源。

### 4.0 项目管理

项目是持久探索图的容器，不等同于一个 Agent session。界面最左侧提供可收缩项目栏，统一展示新建、导入和历史项目；切换项目切换整个探索图，不能串入前一项目的事件或文件。

- 支持新建空项目、快照导入、历史项目重开；项目名称支持修改。
- 支持一级文件夹及重命名；项目可拖动归类，也提供“移至”选择框，文件夹不嵌套。
- 从当前已保存的探索图截面 Fork 一个或多个独立项目，记录来源项目、来源事件水位及截面时间。保留已有方案、实验、精确资源引用和历史执行归属，后续修改互不影响。
- Fork 不是启动 session，不复制在途执行或预算预留，也不停止源项目。副本中未完成的尝试明确标注截面中断和原状态；旧 Agent 只作为历史执行者，等待新 session 接手。
- 当前项目栏的本地项目与目录保存在浏览器 IndexedDB，刷新可恢复，支持导出备份；服务端探索另行列出并订阅实时数据。明确区分本地截面与实时项目，本地新建或 Fork 不宣称已接入服务端执行。跨浏览器同步与发布到执行服务尚不属于本次交互实现。

### 顶部任务信息

顶部只显示算子名；契约、输入 Shape 和环境分别点击展开，基线耗时与当前最佳紧凑并排展示，预算、运行与连接状态保持可见。

契约展示版本明确的 YAML 原文，包含优化目标（正确性与性能目标）、精度要求（参考实现、atol、rtol）及测量协议（预热次数、重复次数、计时边界、同步方式）。Shape 支持一组或多组。缺失字段明确待配置，不从某次实验结果反推约定；实际实验协议与任务契约分别保存，才能检查结果是否满足要求。

### 4.1 双视图联动

- **图视图**：展示整个 探索图的节点和分支关系，支持缩放、展开与定位；展开节点可查看其完整 stage 状态机、执行历史和当前进展。
- **Agent 视图**：按 Agent 展示其参与的节点，以及各节点内负责的 stage 和执行轨迹，能够查看不同 Agent 的并行进展；stage 始终归属于具体节点。
- **实时同步与切换**：两种视图使用同一份节点、阶段和状态数据，实时同步更新；切换时保留当前选中的阶段或节点，并高亮其在另一视图中的对应位置。一个节点涉及多个 Agent 时，应展示对应关联，不复制节点或资源。

### 4.2 节点与右侧文件库

- **逐层浏览**：从任一视图选择节点，查看优化方案、参与执行的 Agent、执行状态和结果摘要，再展开节点内的 stage，查看每个阶段的输入、输出及执行结果。
- **右侧展开**：点击节点后，界面右半部显示该节点的文件库，左侧保留当前视图和选中位置；选择节点内的 stage 时，右侧定位到该阶段关联的文件和记录。
- **资源内容**：文件库展示 kernel、优化思路、阶段总结、实验记录、profile 文件及其他相关产物，支持查看内容；未生成或缺失的内容明确标记。
- **独立与共享资源**：区分节点独有文件与共享引用，显示资源来源和版本；浏览同一共享资源时保持一致，不将引用误显示为节点自己的副本。

### 4.3 关联边与引用知识

在数据支持的情况下，图中的关联边也可点击。选中后在右侧展示关系类型、来源与目标节点，以及该关系关联的引用知识、依据和具体版本；没有记录引用知识时明确显示。派生关系与知识引用关系应能区分，不能仅凭方案派生关系推断引用依据。默认突出多来源派生关系，选中节点时可展开跨分支引用，并定位被引用的节点和知识。

### 4.4 状态与高亮

- **执行状态**：使用颜色、图标和文字区分未开始、进行中、已完成、失败和已停止。
- **内容状态**：使用独立标记显示 hot、ready-for-cool 和 cooled，不与执行状态混用；节点可以同时是“已完成”和“hot”。ready-for-cool 表示已整理为待冷却候选，仍属于 hot，不代表已审批或已合入。
- **联动高亮**：选中阶段、节点或边时，高亮相关 Agent、探索路径和资源引用；两种视图保持一致，并提供状态图例。

界面明确显示当前任务及所查看的版本，实时更新不打断当前浏览位置。状态不能只依赖颜色表达；UI 与 Agent 使用同一套服务数据和操作规则。

## Agent 接入与灵活探索

对使用者提供一个自带 CLI 的算子优化 skill：SKILL.md 指导记录与接手，CLI 负责连接、身份、输入输出和重试，后端执行证据、预算与状态约束。工作台不内置智能 Agent；主 Agent、探索 Agent 都是外部 session，模型启动与编排由外部运行环境承担。

探索图随 Agent 实际上报动态形成，结构稳定、路径开放。Skill 不预设搜索路线，不要求机械地重走所有阶段；回退、重试、带理由跳过与有效结果复用须符合证据约束。不能把未上报的探索当成已被系统自动捕获。

每个 session 独立绑定上下文，默认读取有限摘要并按需加载详情；CLI 返回结构化结果、错误及可执行的修正方向。结果不明的写入必须用原请求身份核对，避免重复实验。真实长任务需独立心跳与外部取消协作，不依赖模型定时发消息。

当前交付为 [可执行 SKILL.md](../skills/operator-exploration/SKILL.md)、[CLI 使用协议](../skills/operator-exploration/references/cli.md) 和 [三个场景](../skills/operator-exploration/references/scenarios.md)。CLI 已覆盖项目创建与导入导出、独立 session 与心跳、节点/资源/Attempt、图关系、交接、检查点与 Fork。合成数据的真实 HTTP/CLI 集成闭环已纳入测试；真实算子执行和外部取消仍需单独验收。

## 5. 基本要求

- **记录可信**：区分事实与假设、实测与预测；保留环境、验证方法和必要证据，信息缺失时明确标记，不将不可比结果直接排名。
- **过程可追溯**：保留探索图、资源引用及修订，支持中断恢复；保护被引用的证据，失败和停止不丢失已有记录。
- **操作受控**：隔离不同探索，遵守预算与停止规则，当前不执行审批或合入；重复或冲突操作不应静默覆盖已有结果。

## 6. 当前验收

当前闭环：多个 Agent 扩展探索图 → 节点内部按 stage 推进并记录实验 → 按规则继续或停止 → 总结并形成 ready-for-cool 候选 → 在双视图中完整回溯。

- **节点与 stage**：能够查看节点从读取依据、形成思路到生成代码、编译验证、性能测量、profiling 和结果总结的完整记录；失败、重试与跳过均有明确状态和依据。
- **双视图联动**：图与 Agent 视图实时同步，切换保留选中的节点或 stage，能够追踪多 Agent 的并行进展。
- **Markdown 展示**：Summary 与 Markdown 文件正确显示标题、列表、表格、链接和代码块；禁用原始 HTML 执行，不将 kernel 源码当 Markdown。
- **资源与引用**：节点右侧文件库可查看 kernel、优化思路、总结、实验与 profile 文件；共享资源来源明确，关联边可追溯知识及跨分支引用的具体版本，缺失内容显式标记。
- **项目与截面**：新建、导入和历史项目可切换、归类和重命名；刷新后恢复目录；同一截面可 Fork 多份，来源可追溯，源项目和副本互不修改，不把历史 session 当作活跃执行者。
- **停止与恢复**：目标达成、预算耗尽、用户停止和分支停止均按约定执行；停止或中断后保留探索图、stage 历史、已有结果和原因，恢复时不覆盖历史。
- **候选与状态**：可从整个图追溯经验候选的支持与反例；执行状态与 hot、ready-for-cool 等内容状态分别显示，不将候选当作已验证或已合入的 cooled 内容。

当前验收不包含人工审批、远端合入或跨任务复用收益评测。

## 7. 后续与待定

后续增强：结构化技能、目录摘要、主动维护和混合检索；完整分支合并、专用图存储和训练导出按实际需要决定。

首版不承诺自动找到最优内核，不替代真机验证，不提供任意 SQL 或文件系统挂载。

待定：技术栈、角色权限、跨服务导入协议、离线能力、产物保留期、首批任务及规模目标。实现建议见[设计文档](design.md)。

## 探索图的核心验收

- 一个方案可融合两个或多个来源，所有来源均可见；多起点合法，派生环路和跨项目端点被拒绝。
- 从节点右侧的经验详情可反向查看支持/反例方案、对应 Attempt 和资源版本，再查看这些方案的来源贡献。
