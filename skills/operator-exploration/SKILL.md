# 算子探索工作台

使用随包的 `scripts/opwork.py`，或安装后使用 `opwork`。先读 [CLI 协议](references/cli.md) 的安装与身份部分；它列出当前实际支持的命令与约束。

探索图保存方案与证据，你决定探索路径。此 skill 不规定优化算法、不启动模型、不替代编译器和设备测试工具。

## 开始与接手

读取 [CLI 协议](references/cli.md) 中的连接、身份和读取部分。确认服务与项目，再为当前真实 session 建立独立上下文。恢复同一真实 session 可复用身份；换 session 必须登记新身份。不能使用另一 session 的上下文文件。

先读取 `context`，明确契约版本、预算、有效结果、在途工作和未完成方向，再按需读取节点、Attempt 和文件。契约缺失或影响实验结论的环境信息未知时，先补齐或明确探索范围，不把未知当兼容。本地浏览器项目须显式导入服务端后才可写入。

若存在未核对的在途实验，先核对外部执行器。请求停止不代表设备停止；没有终态证据时保留未决状态，不能重复派发同一实验。

## 探索中选择记录动作

- 新的优化假设：从一个或多个已有方案创建新节点，说明改动与依据。来源方案不是派发任务的 Agent。
- 同一方案的代码修复或重测：留在节点内追加 Attempt；引用实际依赖及准确资源版本，不覆盖失败历史。
- 跨分支借鉴：记录来源节点、资源版本和用途；融合后重新验证，引用不等同于派生／融合。
- 实际执行前：上传必要输入并申请 Attempt 许可；获准才调用外部执行工具。评测过程中由客户端维护心跳，停止信号交给执行器处理。
- 执行结束：登记实际结果、输入输出与实验协议；工具失败、编译失败、精度失败、性能退化分别记录。命令退出码为零不自动代表正确性通过。
- 原因解释与性能数据分开：未验证的原因仍是猜想，不升级为通用规律。

Stage 是记录阶段，不要求每次机械地完整重走。回退、跳过或复用必须有真实依据；CLI 返回不支持或依赖不满足时，不伪造前序结果来绕过。

## 协作与结束

是否并行、如何分工由主 Agent 决定。可默认让一个探索 session 连续推进一段分支；这不是节点所有权。编译和评测程序本身不登记为智能体。若外部环境支持派发，给新 session 明确项目、任务范围、起点证据、预算与交付；不要传递自己的 session 身份。

结束或交接时保存最佳有效结果、失败方向、未验证假设、在途执行器信息和下一步建议。Session 结束不等于探索图结束。项目暂停、恢复与 Fork 是显式操作；Fork 不启动 Agent，也不取消源项目任务。当前只整理 ready-for-cool，不进行审批、合入或 PR 发布。

按需参考 [三个使用场景](references/scenarios.md)。命令失败先读取结构化错误：超时先核对同一请求的结果，版本冲突先重读事实；不得通过换请求 ID 重复执行结果不明的写入。

## 来源与证据

每个方案可有多个派生来源，分别说明采用的改动。知识与经验是独立图节点；记录 reference 表达借鉴，support/refute 表达有具体实验依据的支持或反例。优先从经验反查证据和方案来源，而不只查看最终最佳节点。没有消融或对照实验时，主要借鉴来源只能作为陈述，不能标成已证实的主要收益来源。
